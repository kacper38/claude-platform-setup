## 2026-10-29 — step 1.2: kit skeleton, guard engine, fixtures

- No separate `kit/` tree: the repo root IS the kit and `kit.manifest` lists what `install.sh --into` copies (init-only vs managed vs mapped dirs), so the files dogfooded here and the files shipped are the same bytes; deviation from plan §8 recorded; revisit if: a shipped file must differ from the dogfooded one (then a template layer for that file only).
- `guard` never emits `allow`: it stays silent and lets the harness's own permission flow run — an explicit `allow` would bypass that flow in Claude Code; only `ask` and `deny` are ever written; revisit if: a harness requires an explicit allow to proceed.
- Deny = JSON on stdout + reason on stderr + exit 2, which both harnesses read as deny; `ask` = JSON + exit 0; guard failure = exit 1 with nothing on stdout, which Claude Code treats as non-blocking and Copilot's preToolUse as deny (documented asymmetry, crash fixtures assert the exit code); revisit if: either harness changes its exit-code contract.
- One Copilot path: `.claude/settings.json` carries `--wrapper claude` and `.github/hooks/guard.json` carries `--wrapper github`; a Copilot-shaped event arriving through the claude wrapper is a no-op, so VS Code (which reads both files) prompts once; revisit if: VS Code stops reading `.github/hooks`.
- Claude Code hook shapes were captured from a real probe session on 2026-10-29 (18 event/tool combinations, redacted, path-normalized, under `tests/fixtures/_shapes/claude`); Copilot shapes are synthesized from the GitHub/VS Code docs and marked so in `_fixture.source` until step 1.3 captures them on the work machine; revisit if: a Copilot capture contradicts a synthesized shape (then the fixture is replaced and the normalizer fixed).
- Subagent marker exists: tool calls made inside a Claude Code subagent carry `agent_id` and `agent_type` in the hook input (SubagentStart/Stop carry them too) — the "main thread never edits" convention can become a hook once telemetry shows it is worth it; revisit if: the step-3.6 ledger shows main-thread edits drive cost.
- `guard.py` is a single stdlib file (Python ≥ 3.9, no third-party imports) so vendoring is one copy and the hook command is one line; split when it passes ~1500 lines; CI runs 3.9 and 3.13; revisit if: a work machine ships an older Python (then a shim).
- Hook budget 5 s in both wrappers, no network in PreToolUse, telemetry writes best-effort — Copilot timeouts fail open, so a slow guard is no guard; revisit if: a rule needs a network call (then it moves to CI).
- A nested `claude -p --dangerously-skip-permissions` probe is not used for fixture capture (blocked by the auto-mode classifier as an unsafe agent, and rightly so); captures come from a normal-permission `claude -p` run in a scratch directory, where PreToolUse fires before the permission check; revisit if: never.
- In this repo `.claude/agents` and `.claude/skills` are symlinks to the root `agents/` and `skills/` (one copy, dogfooded by both harnesses); task repos get real copies through the manifest's `map` lines; revisit if: a harness refuses to follow the symlinks.

## 2026-10-29 — step 1.4: boundary rules in the guard

- Secret-bearing files (`.env*` except `*.example|sample|template|dist`, `*.pem`, `*.key`, `*.p12/pfx/jks`, `*.tfstate*`, `id_*` private keys, `~/.aws/credentials`, `~/.kube/config`, `~/.config/gh/hosts.yml`, `~/.docker/config.json`, `.netrc`, `.pypirc`, `.git-credentials`): Write/Edit → deny, Read → ask, in both harnesses; shell spellings covered (redirects, `tee`, `cp/mv` targets, `sed -i`, `git add` → deny; `cat/jq/grep/source/…` → ask); revisit if: a legitimate workflow writes one of these weekly (then an allowlist knob, never a blanket off).
- `*.tfvars` Write/Edit → ask, not deny (deviation from plan step 1.4): tfvars are daily Terraform work and usually hold sizes and names, not secrets; the prompt asks to confirm no secret values; reads are not judged; revisit if: a tfvars with a real secret is ever committed (then deny + a `.tfvars.example` rule).
- Here-document bodies are data, not commands: `secret-shell`, `git-guard`, `deploy-ask` and `egress-guard` strip them before judging (the delete-guard keeps scanning them, per the owner rule) — found by dogfood: the guard went live in the session that wrote it and denied a commit whose message quoted `echo X=1 > .env`; revisit if: a heredoc is used to smuggle a write past the guard (then the body is scanned for redirect targets only).
- git-guard: deny force pushes (`-f`, `--force`, `--force-with-lease[=…]`, `--force-if-includes`, `+refspec`, `--all`, `--mirror`), pushes whose destination is a protected branch (explicit refspec, `HEAD:main`, or a bare `git push` while the checked-out branch is protected, resolved with `git rev-parse` in the command's cwd, 3 s budget), and `--no-verify` (`commit -n`); protected set from `.claude/guard.json` (`main` by default, `KZ_PROTECTED_BRANCHES` overrides); `gh pr merge` is the way onto `main`; revisit if: a repo needs a release branch (then add it to the set).
- deploy-ask: ask on terraform/tofu apply|destroy|import|taint|state, kubectl apply|create|delete|rollout|drain|scale|patch|exec, helm install|upgrade|uninstall|rollback, docker push, gh workflow run, gh release, az deployment / az … create|delete, CloudFormation deploy|*-stack, aws s3 rm|rb|sync --delete, hcloud server lifecycle, pvesh/qm, pulumi up|destroy, cdk deploy|destroy, ansible-playbook, flux uninstall|suspend; `--dry-run`, `--check`, `--diff`, plan/validate/template/lint/diff never prompt; revisit if: a prompt fires weekly with zero "no" answers (prompt-fatigue review).
- egress-guard is the minimal client-boundary control until the egress screen (step 3.2): with `boundary: client` in `.claude/guard.json` or `KZ_BOUNDARY=client`, other-vendor LLM CLIs (`agy`, `gemini`, `codex`, `llm`, `openai`, `ollama`, `aider`) and curl/wget to LLM API hosts → ask; everything else unchanged; revisit if: step 3.2 lands (then this rule delegates to the screen).
- The Claude-Code-only `permissions` block in `.claude/settings.json` duplicates a subset of the rules (deny writes to `.env*`/pem/key/tfstate, force push, `--no-verify`; ask on tfvars writes and secret reads) as a belt in case the hook is slow or disabled; Copilot ignores the key; revisit if: the two drift (the hook is the source of truth).
- Project hooks are NOT snapshotted at session start: a hook added to `.claude/settings.json` fired in the same Claude Code session that wrote it (observed 2026-10-29); the rev 4 "hook snapshotting" probe is thereby answered; revisit if: a later Claude Code version changes it.
- Fixture corpus is generated: `tools/guard/tests/make_fixtures.py` holds the case tables and writes `tests/fixtures/<rule>/<harness>/<decision>/`; a test fails when the files on disk differ from the generator, so cases are edited in one place; revisit if: never.
- `claude -p --model fable` works (model id `claude-fable-5-1` in `modelUsage`, verified 2026-10-29), so agent frontmatter can pin `fable` by alias; revisit if: the alias disappears.
